Capstone Project

The CS499 Capstone project provided an opportunity to bring together the knowledge and skills developed throughout the Computer Science program. The artifact selected for enhancement was the Fire Department Event Tracker, an Android application originally developed during CS-360 Mobile Architecture and Programming. The application was designed to help organize department meetings, drills, training events, parades, and other departmental activities. Because the application addresses a real-world organizational challenge within the volunteer fire service, it provided an excellent opportunity to demonstrate growth across multiple computer science disciplines.


Developing the Fire Department Event Tracker allowed me to combine my leadership experience in the volunteer fire service with the technical skills developed throughout the Computer Science program, creating a software solution that addresses a real-world organizational need.

Software Design and Engineering Enhancement

The Software Design and Engineering enhancement focused on improving the user experience and maintainability of the application. During this enhancement, I redesigned the user interface using Material 3 design principles, implemented dark mode support, improved input validation, added event time scheduling functionality, and reorganized portions of the code using reusable helper methods. These improvements enhanced both usability and maintainability while demonstrating principles learned throughout software engineering and systems analysis coursework. The enhancement also reinforced the importance of designing software with long-term maintainability and user experience in mind.

Algorithms and Data Structures Enhancement

The Algorithms and Data Structures enhancement focused on improving how event information is organized and presented to users. I implemented dynamic search filtering that allows users to search events by title, date, time, or location. This feature uses linear search and ArrayList traversal techniques to examine event records and display matching results. In addition, I implemented chronological sorting that organizes events based on both date and time values. This required converting stored string values into Date objects so events could be compared and displayed in a logical order. Through this enhancement, I demonstrated practical application of algorithm design, data traversal, sorting techniques, and time complexity analysis. These concepts directly relate to the material covered in CS-300 Data Structures and Algorithms.

Database Enhancement

The Database enhancement focused on improving data management and event lifecycle tracking within the application. I modified the SQLite database schema by introducing a status field that allows events to be categorized as Upcoming, Completed, or Archived. This enhancement required updating the database schema, increasing the database version, modifying SQL operations, updating the Event model, and integrating status management into the user interface. The enhancement demonstrates database design principles, schema evolution, persistent data storage, CRUD operations, and integration between application logic and database systems. These skills build upon concepts learned in DAD-220 and further reinforce the importance of effective database management in software applications.

CS499 Enhancement Categories

The CS499 Capstone project requires students to enhance a software artifact across three major computer science categories. Each category demonstrates different technical skills developed throughout the Computer Science program.


  • Software Design and Engineering: Focuses on user interface improvements, maintainable code structure, software architecture, validation logic, and overall application functionality.

  • Algorithms and Data Structures: Focuses on efficient searching, sorting, filtering, traversal logic, data organization, and time complexity analysis.

  • Databases: Focuses on SQLite database integration, CRUD operations, schema updates, persistent data storage, and efficient data management.

Enhancements

Category One: Software Design and Engineering

Enhancements included:

  • Material 3 UI redesign
  • Dark mode support
  • Improved event validation
  • Event time scheduling support
  • RecyclerView UI enhancements
  • Improved code organization and helper methods
  • Incremental Git branching and commits

AI assistance was used to help generate the project logo and assist with debugging validation logic related to preventing past event creation while allowing current-day events.

Category Two: Algorithms and Data Structures

The second enhancement focused on improving how the application searches, filters, organizes, and displays event data.


I added a dynamic search feature that filters the event list as the user types. The search checks each event's title, date, time, and location fields using an ArrayList-based data structure. This filtering process uses linear search with O(n) time complexity.


I also added chronological sorting so upcoming events are displayed in date and time order. This was implemented using comparator-based sorting with date and time parsing logic, which provides approximately O(n log n) time complexity.


  • Dynamic event search filtering
  • ArrayList event traversal
  • Linear search logic with O(n) time complexity
  • Chronological event sorting
  • Comparator-based sorting with O(n log n) time complexity
  • Date and time parsing for event comparison
  • Dynamic RecyclerView updates based on filtered and sorted data
  • Improved maintainability using reusable helper methods

Category Three: Databases

The third enhancement focused on improving how the application stores, updates, and manages event records in SQLite. This enhancement moved the application beyond basic event creation and deletion by adding event lifecycle tracking.


I updated the SQLite database schema by adding a new event status column and increasing the database version. Event records can now be stored as Upcoming, Completed, or Archived. This allows the application to preserve event history instead of relying only on permanent deletion.


The Event model, DatabaseHelper, and RecyclerView adapter were updated so status values can be written to the database, read back from SQLite, displayed in the event list, and updated through a long-press status management dialog.


  • SQLite schema enhancement with event status column
  • Database version upgrade
  • Event lifecycle tracking
  • Status values for Upcoming, Completed, and Archived
  • Persistent status updates stored in SQLite
  • DatabaseHelper update method for event status management
  • RecyclerView display of database status values
  • Long-press status update dialog
